# 地区节点与本地区自动测速

2026-10-16，当前共 26 个策略组。六个地区选择组：香港、台湾、日本、新加坡、美国、欧洲。每组均保留本地区节点手选，并增加对应的“自动测速”子组。

## 如何使用

例如：💬 Ai平台 → 🇺🇲 美国节点 → 🇺🇲 美国自动测速。

选择自动测速后，只在匹配美国名称的节点中测速选择；也可以返回美国节点组，手动固定美国 01/02。新加坡等其他地区同理。地区选择组默认仍为第一个匹配的节点，自动模式需要用户主动选择；已有 OpenClash 保存选择可能继续沿用。

TG亚太 → 新加坡节点 → 新加坡自动测速；TG北美 → 美国节点 → 美国自动测速；TG欧洲 → 欧洲节点 → 欧洲自动测速。前一步默认引用保持原设置，后一步需主动选择自动测速。

## 地区边界与故障行为

每个自动测速组为 url-test，只包含对应地区节点及 REJECT 占位，不引用全局“♻️ 自动选择”、其他地区或 DIRECT。没有地区节点时只剩 REJECT，防止空组；全部实际节点不可用时不会跨地区兜底，可能仍显示上一次选择或一个失效节点，不能保证显示为 REJECT。

测速地址 https://www.gstatic.com/generate_204，周期 300 秒，延迟容差 50 毫秒。健康检查发现失败且有其他健康候选后，自动选择可用候选；不保证瞬间切换，也不保证已有 TCP 会话无缝迁移。测试地址可达仅说明健康检查结果，不保证每个业务网站都正常。

组内手动选择没有故障自动切换；必须选择对应自动测速子组才启用该行为。全局自动测速仍供通用业务组主动选择，不混入地区选择组。国家/地区识别依靠机场节点名称，需核对真实出口。欧洲包含多个欧洲国家，不保证固定某一个欧洲国家。

## 验证

四套合成订阅覆盖中英文国家节点（含多个美国、新加坡节点）、仅香港、纯英文代码、RUSSIA/AUS/JPG/TWO/HKT 反例。全部通过 Subconverter 0.9.0 转换和 Mihomo 1.19.32 检查。26 组非空、引用无环；每个自动组成员恰好等于其地区手选组中的实际节点加 REJECT，未混入全局自动或其他地区组。规则仍为 8722 条，原 Telegram IP 分类及首次匹配检查通过。没有使用真实机场订阅，未测实机故障恢复时间。

刷新 MiSub 转换结果并更新 OpenClash 订阅，再进入地区组主动选择“本地区自动测速”。若界面仍旧，清除转换缓存或给 INI 地址添加版本参数后重新转换。保持 sort=false。
