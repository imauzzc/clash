# Telegram 分区路由

Telegram 按**目标 IP** 分流。同一账号的消息、媒体、通话会连到不同数据中心，域名也看不出机房位置，所以这里只用 IP 归类。

规则分三份，均在 `config/ACL4SSR_Mini_AI_Custom.ini` 中引用，位置在局域网直连之后、Play / UnBan / 广告 / AI / Google / Proxy / China / GeoIP 之前。

| 规则文件 | 策略组 | 默认出口 |
|---|---|---|
| `rules/Telegram_APAC.list` | `📲 TG亚太` | 🇸🇬 新加坡节点 |
| `rules/Telegram_US.list` | `📲 TG北美` | 🇺🇲 美国节点 |
| `rules/Telegram_Other.list` | `📲 TG兜底` | 🚀 节点选择 |

三个组都可在客户端手动切换，组内保留 `.*` 候选，换出口不需要改规则。

## 分区网段

亚太：新加坡 DC5 及同区域段。

| 网段 | 依据 |
|---|---|
| `91.108.16.0/22` | AS62014，登记 geoloc 新加坡 |
| `91.108.56.0/23` | AS62014，含 Pyrogram 公布的 DC5 端点 91.108.56.130 |
| `149.154.168.0/22` | 含官方 DC5 地址 149.154.171.5 |
| `2001:b28:f23f::/48` | DC5 的 IPv6 段 |

北美：迈阿密 DC1 / DC3。

| 网段 | 依据 |
|---|---|
| `91.108.12.0/22` | AS59930，迈阿密 geoloc |
| `149.154.172.0/22` | 含官方 DC1 / DC3 地址 |
| `2001:b28:f23d::/48` | DC1 / DC3 的 IPv6 段 |

兜底：`rules/Telegram_Other.list` 收录官方 `cidr.txt` 的 14 条网段、欧洲专属的 `95.161.76.100/32`，以及与数据中心无关的域名。欧洲不单独分组，阿姆斯特丹 DC2 / DC4 等欧洲地址同样落在 `📲 TG兜底`，需要固定欧洲出口时在组内手选节点。

## 顺序要求

- 三份地区列表必须先于 `📲 TG兜底` 和 ACL4SSR 的 `Telegram.list`，否则兜底的宽网段会抢先命中。
- 兜底列表内的官方 CIDR 与地区段存在重叠，这是有意的安全网设计；首匹配生效，地区段先命中。
- 同一列表内不要放被前面更宽网段覆盖的 CIDR，那类规则永远不会生效。
- 全部 `IP-CIDR` / `IP-CIDR6` 保留 `no-resolve`，避免为域名额外触发解析。

## 判断边界

- 选址依据是 AS 归属、RIPE 登记与 geoloc，只能说明网络归属，不能严格证明服务器物理位置。
- 分区只改变代理出口，不改变账号归属的数据中心。
- 域名无法判断地区，有真实目标 IP 时先按 IP 命中；没有时走兜底，不按域名猜国家。
- Fake-IP、域名嗅探和 DNS 配置会影响可见的目标地址，排查时以客户端连接详情里的真实 IP 为准。
- 官方 `cidr.txt` 会变动，新增或调整网段后应重新核对。

## 维护

改完列表后刷新 MiSub 转换结果、再更新客户端订阅。新增地区段时放入对应文件并保持 `no-resolve`；删除时先确认没有其他规则依赖同一段。
